Validation Crossrule Classes¶

The datatype classes that are used by the cross rule engine. Ensures that each data type is handled appropriately.

class cc_cross_rule_classes.BaseVariable(name, sheet, series, dfs_by_sheet=None, normalization_schema=None)[source]¶

Bases: object

Parent (base) class for all variable types.

Provides universal predicates (is_blank, equals, etc.) and a common evaluate() interface that subclasses extend.

Each Variable operates only on its own column (Series) and the pre-processed condition dict provided by the CrossRuleEngine. The engine handles:

  • Resolving var_ref → injecting referenced Series into condition[“value”]

  • Selecting the correct subclass for variable type

  • Passing the appropriate DataFrame context

equals(value)[source]¶

Return a Boolean mask where the value equals value.

evaluate(condition: dict)[source]¶

Generic evaluation dispatcher. Subclasses override or extend this. The condition dict should include:

  • op: the operation (e.g. ‘equals’, ‘in’, ‘is_blank’)

  • value(s): supporting arguments depending on op

Notes: - The engine guarantees that value (if present) has already been

resolved (either a scalar, list, or Series).

  • Subclasses can safely assume consistent structure.

in_list(values)[source]¶

Return True where the value is one of values.

is_blank()[source]¶

Return a Boolean mask where the value is missing or empty.

is_not_blank()[source]¶

Inverse of is_blank().

not_in_list(values)[source]¶

Return True where the value is not one of values.
